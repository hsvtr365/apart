# 계정 탈퇴·닉네임 변경 로그·부정 이용 방지 설계

최종 반영 기준: 2026-10-13 (한국 시간)

## 정책

- 탈퇴 회원 행은 삭제하지 않는다. 내부 회원 ID와 글·댓글·좋아요·현장 확인·업로드 연결을 유지한다.
- 탈퇴 시 `withdrawnAt`을 설정하고 닉네임은 **탈퇴_XXXXXXXX**로 변경한다.
- 카카오 원본 회원번호 `kakaoId`, 동 `building`, 모든 세션과 본인에게 온 알림을 삭제한다. 관리자 권한은 회수한다.
- 닉네임 변경 로그는 변경 시각부터 **달력 기준 1년** 보관한다. 윤년 2월 29일은 다음 해 2월 28일로 만료한다.
- 부정 이용 식별값은 활성 계정에서 사용한다. 마지막 활성 계정이 탈퇴하면 탈퇴 시각부터 **1년** 후 만료한다.
- 재가입은 새 회원 ID로 생성하며 기존 글·댓글 수정 권한을 복구하지 않는다.
- 카카오 연결 해제는 아직 자동 구현하지 않았고 별도 연결 해제 안내를 제공한다.
- 식별값과 활동의 연계가 남으므로 완전한 익명화라고 부르지 않는다. 개인정보 처리방침에 보관 목적·기간·접근 제한을 반영해야 한다.

## 데이터 구조

### User

`withdrawnAt`, `abuseIdentityId`, `abuseLinkExpiresAt` 추가. 탈퇴 회원의 추적 연결은 재가입 여부와 관계없이 해당 탈퇴일로부터 1년 후 제거한다. 활성 회원은 만료일 없이 부정 이용 식별값에 연결한다.

### AbuseIdentity

`id = HMAC-SHA256(ABUSE_HMAC_SECRET, "kakao:v1:" + kakaoId)`. 별도의 32바이트 랜덤 서버 비밀키를 사용한다. 원본 카카오 회원번호나 비밀키는 감사 API/로그/브라우저에 출력하지 않는다. `expiresAt`은 활성 회원이 있으면 NULL, 마지막 탈퇴 시 1년 뒤로 지정한다. 키를 임의로 교체하면 기존 식별값과 재가입자를 연결할 수 없으므로 배포 간 유지해야 한다.

### NicknameChangeLog

필드: `userId`, `before`, `after`, `reason`, `createdAt`, `expiresAt`.

지원 사유 코드:

| 코드 | 발생 시점 |
| --- | --- |
| SIGNUP | 새 계정 생성 |
| USER_EDIT | 본인 프로필에서 실제 닉네임 변경 |
| WITHDRAWAL | 탈퇴로 닉네임 전환 |

동만 변경하거나 같은 닉네임을 저장하면 닉네임 로그를 만들지 않는다. 관리자에 의한 타인 프로필 변경 기능은 현재 없어 ADMIN_EDIT 로그도 만들지 않는다. 탈퇴 시 과거 로그의 before/after는 NULL로 지우고 시각·사유만 보존한다. 탈퇴 로그는 before=NULL, after=탈퇴_XXXXXXXX이며 1년 보관한다. 로그를 이용해 원래 닉네임을 복원할 수 없다.

### AccountSecurityEvent

필드: `identityId`, 내부 `userId`, `reason`, 선택 `postId`, `createdAt`, `expiresAt`.

- REGISTER: 신규 가입 또는 재가입
- WITHDRAW: 탈퇴
- DUPLICATE_LIKE: 이전 계정이 같은 글에 남긴 좋아요와 중복되는 요청

각 이벤트는 발생일로부터 1년 후 삭제한다. IP·브라우저 지문·원본 카카오 ID는 수집하지 않는다.

### Like

`abuseIdentityId`를 추가하고 `(abuseIdentityId, postId)` UNIQUE 제약을 적용한다. 동일 카카오 계정의 탈퇴·재가입은 보관 기간 안에서 같은 글에 좋아요를 추가할 수 없다. 이전 좋아요는 탈퇴 계정에 그대로 남기고 추가 요청은 HTTP 409로 거절한다. 재가입자는 이전 계정의 좋아요를 취소하지 못한다. 본인 새 계정의 좋아요 취소는 기존처럼 허용한다.

이전 버전에서 만들어진 좋아요에는 식별값이 없으므로 해당 계정의 다음 로그인·좋아요·탈퇴 시 연결한다. 중복 이전 데이터가 발견되면 기존 식별값의 좋아요 1건을 남기고 중복 행을 제거한다. 보관 기간 만료 후에는 이전 좋아요 수는 남지만 식별 연결이 없어 재가입 중복을 차단하지 못한다. 이는 1년 제한 정책에 따른 동작이다.

## 동시성 및 접근 제어

프로필 변경·탈퇴·좋아요·게시물·댓글·현장 확인·업로드 최종 저장은 회원별 PostgreSQL advisory transaction lock을 공유한다. 게시물 삭제와 변경은 게시물별 lock도 공유하며 잠금 후 현재 상태를 검사한다. 로그인·식별 연결·좋아요는 HMAC별 lock과 DB UNIQUE 제약으로 동시 재가입·동시 클릭을 직렬화한다. 탈퇴 시점 이후 세션이 DB에 남거나 새로 만들어져도 `currentUser()`가 withdrawnAt을 검사해 접근을 거절한다.

관리자 조회: `GET /api/account-audit?userId=회원ID`. permission=0만 허용하며 해당 계정의 최근 닉네임 로그와 연결 계정·가입/탈퇴/중복 좋아요 이벤트를 반환한다. 각 목록은 최신 100건으로 제한한다. 원본 카카오 ID와 HMAC 값은 반환하지 않는다. 만료된 로그와 계정 연결은 정리 작업 이전에도 조회에서 제외한다. 전용 관리 UI는 추가하지 않았다.

## 보관 기간 정리와 배포

- 명령: `cd front && node node_modules/tsx/dist/cli.mjs scripts/cleanup-account-data.ts`
- 현재 운영 호스트는 UTC. 매일 UTC 18:10 = 한국 03:10에 cron 실행한다.
- `deploy/account-retention-cron.sh`가 기존 다른 cron을 유지하면서 지정 작업만 교체한다. 중복 실행은 flock으로 차단한다.
- 삭제 순서: 만료 닉네임 로그·보안 이벤트 삭제 → 탈퇴 계정/좋아요의 만료 식별 연결 해제 → 만료 AbuseIdentity 삭제.
- 회원 행·글·댓글·좋아요 자체는 삭제하지 않는다. 정리 로그에는 처리 건수만 출력한다.
- 만료 데이터의 실제 삭제는 정상 cron 기준 최대 하루 지연될 수 있다. 로그인·좋아요·탈퇴에서는 해당 HMAC의 만료 연결만 검사·제거한다. 전 계정 로그 정리는 일일 cron에서 실행한다. 중복 좋아요를 409로 거절할 때도 부정 이용 감사 이벤트는 commit한다.
- `pm2_start.sh`에서 `provision-abuse-secret.cjs`로 서버 .env의 비밀키를 생성하고 migration·빌드·cron 설치를 실행한다. 이미 설정된 키는 교체하지 않는다.
- migration: `202610130001_account_retention`.

## 기존 데이터와 한계

이전 구현에서 실제 회원 행을 삭제하고 공용 retired-neighbor로 합친 기록은 원래 카카오 ID와 회원별 작성 관계를 복원할 수 없다. 공용 계정 이름은 탈퇴한 이용자로 바꾸고 탈퇴 상태로 처리한다. 신규 로그는 적용 이후부터 쌓이며 과거 변경 이력은 생성하지 않는다.

HMAC는 같은 서비스의 같은 카카오 회원번호를 연결한다. 별도의 카카오 계정을 만드는 공격이나 카카오에서 식별번호가 바뀌는 상황은 탐지하지 않는다. 가입 횟수만으로 자동 제재하지 않는다. 부정 이용 식별값 1년 보관은 운영상 채택한 기준으로, 법정 보관기간을 의미하지 않는다. 약관·개인정보 처리방침의 정식 확정과 카카오 자동 unlink는 별도 작업이다.

## 검증

분리된 임시 DB에서 migration, 탈퇴 행 유지·개인 식별정보 제거·활동 유지, 재가입 새 ID, 동시 중복 좋아요 거절, 변경 사유 로그, 탈퇴 시 과거 닉네임 제거, 로그 및 식별 연결 만료 삭제, 관리자 API 권한과 식별값 비노출을 검사한다. 실제 운영 계정의 탈퇴를 테스트하지 않는다.

## 탈퇴 계정 표시 이름 보강

2026-10-13: 계정별 고정 이름 `탈퇴_XXXXXXXX`을 표시한다. 코드는 내부 회원 ID 마지막 8글자를 대문자로 표시한 값이며 카카오 ID·HMAC·과거 닉네임을 사용하지 않는다. 글·댓글·확인 기록의 author/user 참조는 유지하므로 같은 탈퇴 계정의 표시 이름도 같다. 표시 코드는 로그인이나 권한 검증의 식별자로 사용하지 않는다. 기존 탈퇴 계정에도 migration `202610130002_withdrawn_labels`로 적용한다. 과거 공용 계정으로 합쳐진 기록은 분리할 수 없다.
